# Reference Motion UI Preset

Use only when the user asks for the information-stage and motion rhythm of a supplied reference. Learn its organization without copying identity.

## Presenter Motion UI

### Scene A — Full Presenter Background

- Purpose: Hook, chapter handoff, key viewpoint, Ending.
- Use the real human background; light dim/blur is allowed.
- Human occupies roughly 30%–45%; cards use actual negative space and never cover the face.
- Optional elements: title change, tool badge, data/keyword card, progress rail, restrained glow.
- Avoid a large webcam-style border.

### Scene B — Full Motion Canvas

- Purpose: input→process→output, Skill/Agent flow, Before/After, data or structure change.
- Motion is full-screen; Presenter becomes a 12%–17% rounded/circular PIP or disappears.
- Require visible state progression, not a static slide with moving decoration.

### Scene C — Real Screen Demo

- Purpose: Prompt input, actual software action, real result, project page.
- Screen owns the canvas; Presenter is small or hidden.
- Use `Live → Freeze → Explain → Continue` and calibrated annotation.
- Never fabricate a product screen.

## Optional Dark Motion UI

- Deep navy/gray canvas, restrained cyan/purple/yellow accents, subtle grid/texture, progress rail, controlled glow, result lock.
- No cyber noise, code rain, strobing, or unmotivated neon.

## Editorial Brand override

When project tokens specify cream, deep brown, orange, or another established palette, keep them. Import only layout rhythm, motion density, state progression, Presenter relation, subtitle restraint, and SFX timing.
