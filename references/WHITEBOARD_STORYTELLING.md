# Whiteboard Storytelling / Comedy Animation

Read this reference only after the content router selects `WHITEBOARD_STORYTELLING`.

## Outcome

Translate an abstract knowledge goal into:

```text
Story + Progressive Drawing + Character Action + Visual Comedy + Knowledge Lock
```

The viewer should feel that someone is drawing and directing a small animation while explaining—not that a slide deck is moving.

## Planning order

```text
Script → Knowledge Goal → Story Shell → Comedy Punches → Visual Beats
→ Draw Plan → Asset Gap → Clean A-roll → Lock → Motion → SFX → Caption → QC
```

Do not collect assets first and invent a story around them. Series identity comes from the whiteboard, Hand, progressive build, comedy timing, knowledge lock, and character reaction—not from repeating one setting.

## Draw Before Show

When an object can reasonably be established by drawing, let the audience see it form.

1. **True Stroke Drawing** — handwriting, arrows, lines, circles, marks, mountains, and simple props.
2. **Progressive Mask Drawing** — medium-complex characters, buildings, props, and poses. The mask front follows the pen tip.
3. **Assembly Build** — complex character or object built as semantic parts, for example head → eyes → body → hands → prop → expression.
4. **Instant Pop / Reveal** — reserve for comedy impact, surprise, error, explosion, sudden prop, or another intentional punch. It is not the default asset entrance.

### Hand tip contract

`HAND TIP = CURRENT STROKE ENDPOINT OR MASK FRONT`.

A Hand moving nearby while text, a character, or an image fades in independently is `FAKE_HANDWRITING` and fails. Pen-down sound follows active drawing; it stops on pen lift.

## Progressive scene construction

Prefer one scene that grows:

```text
Object A appears
→ Object B grows inside or beside A
→ Object C emerges from B
→ actions and relationships increase scene meaning
```

Do not hard-code a proven example's objects or story shell. The transferable rule is nested construction and increasing meaning. A new slide is justified only when the viewer's task or world genuinely changes.

## Character direction

Use limited animation with personality:

```text
Start State → Action → Reaction → Result
```

Available techniques include pose/expression swap, anticipation, overshoot, squash/stretch, rotate, translate, motion line, reaction pause, punch-in, and prop interaction. A fixed character plus changing labels is not enough.

For a recurring character, prefer an episode arc such as:

```text
Normal → Problem → Attempt → Failure → Learning → New Problem
```

Lock a base/feet anchor for pose swaps. Keep only one character state visible per temporal state unless duplication is intentional and explained. Do not flip an asset containing text, a logo, or a directional prop; flip character-only layers and keep text readable.

## Comedy

A Comedy Punch is a funny visual situation, not a sticker or funny word. Use as many as the subject earns; 3–5 is a useful range, while serious topics may use 0–2.

```text
Setup → Anticipation → Pause → Impact → Reaction
```

Reaction is required. Preserve its pause during A-roll cleanup. Prefer `Visual Conflict → Audience Question → Explanation → Knowledge Term` for consumer explanation. Meme language may support knowledge, but accuracy and durable meaning win over trends.

## Knowledge Hero

Prefer one core knowledge lock per episode:

- extreme simplicity and large empty space;
- handwritten core relationship;
- one restrained emphasis color;
- no competing character, card, or UI;
- completed frame holds about 0.8–1.5 seconds when the voice permits.

Empty space is functional during comedy reaction, question, and Knowledge Hero beats. Do not fill the canvas merely to look rich.

## One beat, one idea

Every visual beat has one primary meaning. Auxiliary elements may support it, but character, labels, arrows, props, terms, and captions must not compete equally. Split or simplify an overloaded frame.

## Full canvas and captions

Use the full whiteboard as the story space. Keep safe margins and a floating bottom caption area, but do not create a visible 75/25 divider or course-template boundary.

Default caption: semantic, single line, short, stable, and visually subordinate. It is not a transcript. Compress wording before reducing size.

## Voice–visual contract

Map every important line:

```text
Intended Meaning → Visual Event → Completion/Reaction
```

Do not leave Visual A after voice reaches B, or reveal C while voice is still on B. Important completion should land near the spoken keyword; about 100–200ms anticipation may be useful. Validate from the locked Clean A-roll and current timeline, not an old preview timecode.

## SFX as story layer

Every cue binds to a visible `DRAW`, `MOTION`, `IMPACT`, `COMEDY`, or `REVEAL` event. `IMPACT FRAME = SFX HIT`. Use separate tracks, keep dialogue dominant, trim drawing sound to pen-down intervals, and avoid continuous decorative noise.

## Assets

Do not generate a complete multi-panel storyboard and play it as sequential PNGs. Generate or retain images only for complex poses, special expressions, unique comedy props, meme punches, or details that are genuinely hard to build programmatically.

An asset sheet is a source library:

```text
Extract → Clean → Transparent → Individual Asset → Animate → Review
```

Reject source-board edges, warm-white rectangles, halos, neighbors, and baked text. Use programmatic text, arrows, boxes, bubbles, simple props, and basic characters where practical.

## Timing and duration

- ordinary visual change: roughly 1.5–3s;
- comedy action chain: roughly 0.2–1s per action;
- Hero drawing: roughly 0.8–2s;
- Knowledge hold: roughly 0.8–1.5s.

These follow voice rhythm rather than a timer. Consumer whiteboard episodes are commonly 45–100s; a complex story may reach 100–120s. Over 120s requires an explicit check for repetition, over-explanation, PPT holds, caption redundancy, and unnecessary beats.

## Hook

Within 1–3 seconds, create a question, conflict, surprise, or visual event. Useful forms include absurd result, character conflict, wrong belief, relatable situation, extreme analogy, or an internet-style punchline. Do not default to a fixed rhetorical opener.

## PPT and UI residue

Ask whether a single still frame already communicates the entire beat. If yes, review for excessive static-slide thinking. Meaning that depends on change, reaction, reveal, or build has higher animation value. A Knowledge Hero is an intentional exception.

Generic app cards, product toggles, dashboards, rectangular controls, and SaaS panels are prohibited unless real UI is part of the story. Prefer handwriting, bubbles, sketches, physical choices, and character interaction.

## Human gate

No validator can guarantee that the story is interesting, comedy lands, drawing feels natural, a meme is not awkward, character taste is strong, or voice/visual meaning is correct. A person approves hook, punch, reaction, Knowledge Hero, draw-on, SFX, ending, and final release.
